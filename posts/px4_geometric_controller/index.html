PX4是一个能够非常方便进行二次开发的无人机飞控。对于科研的实验算法复现，可以使用PX4开放给开发者的app来完成，本文所复现的几何控制器完成了PX4中混控器之前所有控制器件的作用，最终输出规一化的力和力矩。

PX4 二次开发#

PX4源码的目录下面有两个文件夹，/src/examples和/src/modules，前者是专门留给用户进行自定义算法app实现，后者则是将PX4原生的控制器暴露在用户面前，用户可以自定义飞控中控制器的开关。我现在复现的几何控制器就是完全基于app的模板，PX4官网也有相关的说明。本文的所参照的是PX4中workitem的模板写法，用户可以在nsh终端通过appname start命令来进行程序的启动。

内部通信#

PX4与ROS中的通信机制极为相似。

在ROS1中消息是publisher节点向ROS master注册topic(维护注册表)，在subscriber节点向ROS master发送订阅请求后，ROS master打通发布者和订阅者之间的p2p连接。

在PX4采用uORB(micro Object Request Broker)通讯总线实现，publisher发布的uORB topic通过Device Master维护的DeviceNode表格(内部缓冲),subscriber只需要访问DeviceNode表格就行。

当然在接受数据后的处理层面也有一些不一样，ROS中主要是通过注册回调的方式实现，PX4中可以通过主动轮询实现（也可以注册回调）。

在PX4中，自定义一个uORB topic需要进入/msg文件夹下面新建.msg文件，或者在已有的.msg文件内部做话题复用。

任务调度#

PX4中，任务调度可以通过2中不同的方式调度：Tasks(任务)和Work queue tasks(工作队列任务)实现，具体可以看我的下一篇文章。

offboard模式#

在普通模式下（如Position、Attitude、Acro），飞控根据遥控器输入和自身控制逻辑来飞行。

在offboard模式下，飞行器根据飞控外部（如机载电脑）提供的设定值控制位置、速度、加速度、姿态以及推力/力矩，这些设定值可以使用mavlink，也可以使用在PX4内部用户自定义app发布。

模式的切换需要向话题action_request发布offboard请求，结构如下：

	action_request_s action_request{};
	action_request.timestamp = now;
	action_request.action = action_request_s::ACTION_SWITCH_MODE;
	action_request.source = action_request_s::SOURCE_RC_SWITCH;
	action_request.mode = vehicle_status_s::NAVIGATION_STATE_OFFBOARD;
	_action_request_pub.publish(action_request);

与此同时还要，向话题offboard_control_mode不停发布消息，因为PX4内部的自保护机制，要求在offboard模式下这个话题必须要有2Hz的发布频率，不然就会自动退出offboard模式。

PX4 requires that the external controller provides a continuous 2Hz “proof of life” signal, by streaming any of the supported MAVLink setpoint messages or the ROS 2 OffboardControlMode message. PX4 enables switching to offboard control mode only after receiving the signal for more than a second, and will failsafe (controlled by COM_OBL_RC_ACT) if the signal stops.

话题结构如下，后续实现的几何控制器是要控制到转矩和推力的，所以就将其他的全部关闭，只保留最后一个。

	offboard_control_mode_s offboard_ctrl_mode{};
	offboard_ctrl_mode.timestamp = hrt_absolute_time();
	offboard_ctrl_mode.position = false;
	offboard_ctrl_mode.velocity = false;
	offboard_ctrl_mode.acceleration = false;
	offboard_ctrl_mode.attitude = false;
	offboard_ctrl_mode.thrust_and_torque = true;
	_offboard_ctrl_pub.publish(offboard_ctrl_mode);

几何控制器#

这张图取自几何控制器论文原文，控制器部分则是代替了上面那张PX4控制框图中mixer之前的所有部分。

控制器型式如下：

\begin{aligned} f &= -\left( -k_x e_x - k_v e_v - mg e_3 + m\ddot{x}_d \right)\cdot R e_3, \\ M &= -k_R e_R - k_\Omega e_\Omega + \Omega \times J\Omega \\ &\quad - J\left( \hat{\Omega} R^{T} R_d \Omega_d - R^{T} R_d \dot{\Omega}_d \right). \end{aligned}

为了简化控制器，我们去掉了一些比较复杂的项。

	_acc_command = _des_acc + _pos_error.emult(_pos_gain) + _vel_error.emult(_vel_gain) - g;


	const matrix::Quatf q_att{_vehicle_attitude.q};
	const matrix::Dcmf R_b_w(q_att);

	const matrix::Matrix3f e_R_matrix = 0.5f * (R_d_w.transpose() * R_b_w - 
                                        R_b_w.   transpose() * R_d_w);
	Vector3f e_R;
	e_R(0) = e_R_matrix(2, 1);
	e_R(1) = e_R_matrix(0, 2);
	e_R(2) = e_R_matrix(1, 0);

	const Vector3f omega(_vehicle_angular_velocity.xyz);
	const Vector3f omega_ref(0.0f, 0.0f, 0.0f);
	const Vector3f omega_d_b = R_b_w.transpose() * R_d_w * omega_ref;
	const Vector3f e_omega = omega - omega_d_b;

	Vector3f tau = -_attitude_gain.emult(e_R) - _angular_rate_gain.emult(e_omega) + omega.cross(_inertia_diag.emult(omega));

这里计算得到的_acc_command可以理解为目标加速度，乘以m就可以得到推力。

由于无人机的推力合力始终垂直于机体平面，所以目标姿态的获取是可以通过目标加速度和目标航向角结算得到，这也就是PX4控制框图中Acceleration and Yaw to Attitude所在干的事情。

规一化控制量问题#

PX4中混控器所接受的是规一化的推力和力矩，也就是要将这些量分别映射到[0,1]之间，或者[-1,1]之间。

这里我总结了两种思路。

  • 已知无人机机身所有的参数，包括连杆长度，机身重量，转动惯量，电机推力系数等。然后从推力转矩通过数学推导逐步映射到电机规一化油门，然后再逆变换得到规一化的推力和力矩。

  • 先验参数未知。参考PX4的悬停油门量估计，可以知道加速度和油门之间的映射，同理可以估计角加速度到力矩油门之间的映射，但这只是一个猜想，等待验证。
